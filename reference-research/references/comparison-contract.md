# 比较合同

## 比较单位

围绕同一道问题按共同维度比较，不要先分别总结每个项目再尝试拼接。

需要时检查这些维度：

- 对象与稳定身份；
- Module、Interface、Implementation 和 Seam；
- 状态和生命周期；
- 权限、授权与当前范围；
- 执行、幂等和并发；
- 持久化、版本和历史；
- 失败、中断、恢复和结果未知；
- 审计与证据；
- 外部来源和写回；
- 用户交互与确认。

只选与当前问题有关的维度，不强制填满全部类别。

## 比较发现

使用稳定 ID `RR-C001`，记录：

- 比较维度；
- 参考实现；
- 当前产品实现或已确认设计；
- 实质差异；
- 产品影响；
- 支撑证据 ID。

不要把 Session、目录、文件路径、ACL、日志或技术 token 自动映射成正式产品对象。

## 可迁移性

| 内部标识 | 用户显示 | 含义 |
| --- | --- | --- |
| `PRINCIPLE_CAN_TRANSFER` | 原则可迁移 | 原则与当前产品语义兼容，但仍需产品确认 |
| `ADAPTER_REQUIRED` | 需要适配转译 | 技术机制可用，但必须经过明确的产品或运行时 Adapter |
| `INTERACTION_REFERENCE_ONLY` | 仅作交互参考 | 只能启发交互，不构成对象、权限或持久化合同 |
| `NOT_TRANSFERABLE` | 不可迁移 | 与当前正式对象、治理或来源权威冲突 |

每项判断都要写明原因和受保护的产品边界。

## 优化候选

使用稳定 ID `RR-O001`，状态固定为 `PROPOSED_NOT_CONFIRMED`，用户显示为 `待用户确认`。

每项记录：

- 当前问题；
- 建议改变；
- 支撑证据 ID；
- 影响对象和已有决定；
- 预期收益；
- 风险；
- 不可迁移边界；
- 下一验证类型。

下一验证类型只允许：`PRODUCT_QUESTION`、`TECHNICAL_SPIKE`、`PROTOTYPE`、`MORE_RESEARCH`、`NONE`。
